## Findings worth acting on

1. **`separator` has zero call sites in `apps/web`.** Only `DropdownMenuSeparator` (a different component) is
   used. Either delete the dead web copy in the same PR (no behaviour change possible) or leave it. Recommend
   deleting it with the wave, not importing it.
2. **One stray reference**: `features/reports/lib/status.ts:3` mentions `components/ui/badge` in a comment only.
   Not a call site; update the comment when `badge` moves.
3. **Plumbing is the real work, not the components.** Before any import can switch to `@rakhal/ui/ui/x`,
   `apps/web` needs what `apps/admin` already has (do this once, as "M3-0", before wave 1):
   - `"@rakhal/ui": "workspace:*"` in `apps/web/package.json`;
   - `transpilePackages: ["@rakhal/ui"]` in `apps/web/next.config.ts` (the package ships TypeScript source);
   - `@source "../../../packages/ui/src";` in `apps/web/app/globals.css` (Tailwind v4 only scans files it can
     see; without this, every class that exists only inside `packages/ui` silently drops out of the CSS). This is
     the single most likely cause of a visual regression in the whole migration;
   - vitest and ESLint in `apps/web` must resolve and lint the workspace package (check `import/no-cycle`
     config and the vitest alias).
4. **Token drift is one line.** Comparing `apps/web/app/globals.css` with `packages/ui/src/styles/tokens.css`
   per selector and variable: 148 of 149 shared declarations are identical (light and dark). The one difference
   is `--font-sans` in `@theme inline`: web has `var(--font-latin), var(--font-bengali), -apple-system,
   BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif`; the shared package has `var(--font-latin), system-ui,
   sans-serif`. Per principle 2 the consumer wins, so the shared token must adopt the Bengali fallback (and
   admin will pick it up; confirm that is acceptable). The web file also holds 78 consumer-only declarations
   (`--session-*`, `--state-*`, `--cream`, `--chart-*`, `*-text` variants) that stay in the app.
5. **Churn risk on the original.** While the original repo remains the source of truth (M1-M5), 3 commits
   touched `components/ui` in the last 30 days (1 touched a wave-1 file in 60 days; last on 2026-10-28), and 39
   commits touched the app overall. Wave 1 is low risk for conflicts; later waves (dialog, sheet, tabs) are the
   ones being edited.

## Proposed shape of the wave 1 PR (not started)

M3-0 plumbing PR (no component change, visual gate must show zero diff), then one PR per component, each: swap
the import with a codemod, delete the local file, run the gate. `separator` is a delete-only PR. Order by
risk, lowest first: `skeleton`, `card`, `badge`, `label`, `textarea`, `switch`, `checkbox`, `radio-group`,
`button` last (241 call sites, also used by admin).
