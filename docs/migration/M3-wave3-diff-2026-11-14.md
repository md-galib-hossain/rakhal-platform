## Result in one line

**7 of 11 real components are identical apart from import paths.** **Three have a real difference, and in
all three the shared copy is the stripped-down one — web wins, same as wave 2's `tabs`/`labeled-field`:**
`page-card`, `stat-card`, `card-skeleton`. **One component (`pagination`) has no shared copy at all** and
imports a `lib/*` hook, so it is not eligible as-is. **New finding this wave: `empty-state`, `page-header`,
`page-card` and `stat-card` already have real admin consumers on the *shared* (non-web) behaviour today** —
unlike every wave 1/2 reconciliation, where the admin had zero call sites. Reconciling `page-card`/`stat-card`
toward web's version will change admin's live rendering, not just add a new consumer.

## The three real differences

`page-card`: web's root `div` carries `flex-1 min-h-[calc(100vh-6.75rem)]` so the card stretches to fill the
viewport against the sticky sidebar; the shared copy is a plain `flex flex-col` with no minimum height. Admin's
3 call sites (`audit`, `farms`, `users`) already import `@rakhal/ui/shared/page-card` — the short version — so
admin's cards today do **not** stretch. If web wins (per principle 2), reconciling pushes the taller behaviour
into admin too; the owner should decide whether admin's shorter page cards were intentional or just unported.

`stat-card`: web's value text has `tracking-tight tabular-nums`; the shared copy drops both, so numeric columns
in the shared version aren't monospaced and sit slightly looser. Admin's one call site (dashboard) is already on
the shared version without this, so reconciling changes admin's number rendering.

`card-skeleton`: web's wrapping `Card` has `h-full min-h-[220px]`; the shared copy lacks it. No admin consumer,
so this one is a clean "port web's class in" with no live admin impact — closer to wave 1/2's pattern than the
two above.

## `pagination`

No `packages/ui` copy exists; this is a "move + create" task, not a diff. It imports `PAGE_SIZE_OPTIONS` from
`@/lib/hooks/use-cursor-pager`, a `lib/*` import, which per principle 5 makes it ineligible as-is. Before it can
move, either the constant moves with it (into the component's own default, or a small shared constants file) or
`pageSizeOptions` becomes a required prop with no default import. No `next-intl`/`nuqs`/`features/*` dependency,
so once that one import is resolved it's otherwise eligible.

### Gate gaps worth closing first (optional, same pattern as wave 2's #15)

`stat-card` and `row-actions-menu` have zero visual coverage; `error-state` only renders inside an `ErrorBoundary`,
which no current spec triggers. Unlike wave 2, several of phase 1's items (`row-actions-menu`, `mobile-record-card`,
`table-skeleton`) are also uncovered, but all are byte-identical files with no admin consumer, so the wave-2
fallback (identical file + full unit-test suite) is a reasonable bar without building new screens for every one.
`page-card` and `stat-card` are the ones where new coverage would matter most, since they also change live admin
output — but building a screen that triggers an empty/error state or that renders stat cards is more work than
this migration strictly needs; flagging it as optional, not blocking.

### Owner decisions needed

1. **`page-card`**: keep the taller web variant (reconcile, changes admin's 3 pages) or keep the shared short

2. **`stat-card`**: add `tracking-tight tabular-nums` to the shared copy (changes admin's 1 page's numeral

3. **`pagination`**: worth creating in `packages/ui` now, given zero gate coverage and a blocking `lib/*` import

4. Batching: as with wave 2, one PR per component versus a few batched PRs — your call.
